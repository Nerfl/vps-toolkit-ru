# VPS Toolkit RU

Интерактивный Bash-инструмент для первоначальной проверки, защиты и обслуживания удалённого VPS. Интерфейс инструмента написан на русском языке. Первая рабочая версия — **0.1.0**.

## Поддерживаемые системы

- Ubuntu 22.04 LTS
- Ubuntu 24.04 LTS

Запуск требует прав `root`. Другие дистрибутивы и версии пока не поддерживаются.

## Возможности версии 0.1.0

1. **Аудит без изменений:** система, ресурсы, SSH, события входа за 24 часа, Fail2Ban, BBR, firewall, слушающие порты и Docker.
2. **Обновление системы:** проверка доступных обновлений, `apt-get update`, а также `apt-get update` и `apt-get upgrade` после подтверждения. После обновления списков симуляция показывает количество и имена планируемых пакетов; непосредственно перед `upgrade` запрашивается отдельное подтверждение и выводится предупреждение о возможном перезапуске служб. Существующие файлы настроек пакетов сохраняются при конфликте; автоматические `autoremove`, `dist-upgrade` и `full-upgrade` не запускаются. При необходимости перезагрузки задаётся отдельный вопрос; автоматической перезагрузки нет.
3. **Fail2Ban:** установка и отдельная настройка jail `sshd`, проверка, список блокировок, журнал и ручная разблокировка IP. Стандартные параметры: 5 попыток за 10 минут, блокировка на 1 час, backend `systemd`.
4. **BBR:** проверка поддержки, включение и отключение через отдельный файл `sysctl.d`, проверка активных значений.
5. **Сводная информация о сервере** и **история действий**.

Настройки SSH (`PermitRootLogin`, `PasswordAuthentication`, порт) инструмент не меняет. Firewall только проверяется. Docker в этой версии только обнаруживается.

## Получение и запуск

После публикации репозитория:

```bash
git clone https://github.com/Nerfl/vps-toolkit-ru.git
cd vps-toolkit-ru
chmod +x install.sh
sudo ./install.sh
```

Для уже скачанной копии достаточно последних трёх команд. В текущем выпуске `install.sh` — главный файл запуска; он не устанавливает фоновый сервис и не скачивает код.

Для просмотра запланированных изменений:

```bash
sudo ./install.sh --dry-run
```

В этом режиме действия с системой не выполняются и журнал не создаётся. Аудит и информационные экраны работают как обычно и сами не создают журнал. Все пункты обновления в режиме просмотра обходятся без вызова apt, включая симуляцию; количество пакетов в этом режиме неизвестно. В обычном режиме проверка доступных обновлений использует локальные списки apt. Если apt/dpkg занят, инструмент сообщает об этом и не удаляет lock-файлы.

## Важное для удалённого VPS

Перед обновлением системы или настройкой Fail2Ban сохраните действующее SSH-подключение и убедитесь, что доступна консоль провайдера. Настройка Fail2Ban требует отдельного подтверждения такого доступа. Fail2Ban может временно заблокировать ваш IP после повторных неверных попыток входа. Инструмент не отключает парольный вход, не запрещает вход `root`, не меняет порт SSH и не включает firewall. Наличие разрешённого входа `root` по паролю отмечается как рекомендация, а не как доказательство взлома.

Для изменений требуется подтверждение в меню. Ошибка проверки конфигурации Fail2Ban или применения BBR запускает откат соответствующего файла и параметров, если это возможно. После изменения всегда проверяется фактическое состояние. Перед изменением существующего файла создаётся его копия.

## Fail2Ban

Инструмент записывает только `/etc/fail2ban/jail.d/vps-toolkit-sshd.local` и не перезаписывает `/etc/fail2ban/jail.local`. Если найдена пользовательская конфигурация или уже работающий SSH jail без файла toolkit, автоматическая настройка останавливается с предупреждением. Изменённый вручную файл toolkit также не перезаписывается. Автоматическая настройка рассчитана на единственный порт SSH 22: она сверяет `sshd -T` с TCP listener основного процесса `ssh.service` по `MainPID` либо с настройкой `ssh.socket` и её фактическим listener. Сокеты дочерних SSH-сессий для X11 forwarding не считаются серверным портом. При другом или неизвестном порте настройка отменяется. В jail явно задан `port = 22`; действующие `maxretry`, `findtime` и `bantime` проверяются через `fail2ban-client`. Для SSH используется backend `systemd`. Журнал исходных событий SSH и Fail2Ban может содержать системные сообщения на языке самой ОС.

## BBR

Настройка хранится в `/etc/sysctl.d/99-vps-toolkit-bbr.conf`; весь `/etc/sysctl.conf` не переписывается. Включаются `net.core.default_qdisc=fq` и `net.ipv4.tcp_congestion_control=bbr`. Перед включением инструмент читает определения этих параметров в `/etc/sysctl.conf`, `/etc/sysctl.d/`, `/run/sysctl.d/`, `/usr/local/lib/sysctl.d/`, `/usr/lib/sysctl.d/` и `/lib/sysctl.d/`; при конфликте показывает файл и значение и отменяет изменение. Чужие файлы не меняются. Предыдущие значения записываются в комментарии файла и используются при отключении. Уже настроенный вне toolkit BBR не присваивается инструментом; изменённый вручную файл toolkit не перезаписывается и не удаляется. Если прежний TCP-алгоритм недоступен, предлагается `cubic`, только когда он доступен. BBR относится к TCP; для UDP, QUIC и Hysteria2 прямого эффекта нет. Польза для конкретной нагрузки и постоянство настройки после перезагрузки не гарантируются; проверьте состояние после следующей плановой перезагрузки.

## Резервные копии и журнал

Копии изменяемых существующих конфигураций находятся в `/var/backups/vps-toolkit-ru/YYYYMMDD-HHMMSS/` с сохранением исходного пути. Одинаковое содержимое в рамках одного запуска не копируется повторно; если файл успел измениться, создаётся отдельная копия. Действия записываются в `/var/log/vps-toolkit-ru.log`; журнал не предназначен для хранения паролей, токенов и ключей.

## Структура

```text
install.sh                 Главное меню и проверка запуска
VERSION                    Версия выпуска
lib/colors.sh              Цветные сообщения
lib/common.sh              Общие безопасные функции
lib/backup.sh              Резервные копии
lib/logging.sh             Журнал действий
modules/audit.sh           Аудит
modules/update.sh          Обновление apt
modules/fail2ban.sh        Защита SSH через Fail2Ban
modules/bbr.sh             Настройка BBR
modules/system-info.sh     Сводная информация
tests/smoke-test.sh        Безопасные проверки
```

## Проверка исходников

```bash
find . -type f -name '*.sh' -print0 | xargs -0 -n1 bash -n
bash tests/smoke-test.sh
```

Если `shellcheck` уже установлен, можно выполнить `find . -type f -name '*.sh' -print0 | xargs -0 shellcheck`. Он не устанавливается автоматически.
